## ٠. القواعد الحاكمة (ثابتة قبل أي كود)

1. **الاعتماد أولاً:** كل بند يُعرض للمناقشة ويُوافق عليه قبل كتابة كوده. يحق لك إيقافي أو تغيير الاتجاه في أي نقطة.
2. **بند ببند:** لا أفتح بنداً جديداً قبل تجربة السابق وتوثيقه ودفعه. لكل بند: خطة → تنفيذ → تجربة Mock محلية → إدخال في `docs/IMPROVEMENTS-LOG.md` → `typecheck` / `lint` / `build` → commit + push → تقرير عربي.
3. **ويب فقط أولاً** (متجاوب RTL). أي Flutter أو Three.js أو GSAP أو Lenis **خارج النطاق** إلا بطلب صريح.
4. **`cacheComponents: true` و`partialPrefetching: true` يبقيان مفعّلين** في `next.config.ts`؛ أي كود جديد يجب ألا يكسر الـ prerender ولا يضيف `new Date()` وقت التصيير.
5. **حزم مجانية فقط.** لا Higgsfield ولا Claude مدفوع ولا MCP مُفعّل. Cloudinary الحالي (٤ متغيرات منفصلة، بدون `CLOUDINARY_URL`) كافٍ.
6. **لا أسرار في الشات ولا في `.env.example`.** أي مفاتيح لاحقاً توضع أنت في Vercel / GitHub Secrets.
7. **النصوص الحساسة لا تُمس:** الدفع يظل حرفياً `تحويل بنكي أو كاش عند الوصول`؛ صياغة الشروط والخصوصية معتمدة؛ الدعم `01066094050` / واتساب `https://wa.me/201066094050` / تليجرام `https://t.me/+201066094050`؛ Tawk كما هو «سيبها دلوقتى يا بطل».
8. **لا تغيير في قاعدة البيانات الإنتاجية** لهذه البنود، ولا تحويل بنكي حقيقي، ولا Payouts، ولا تغيير للنطاق، ولا دفع حي.
9. **التجارب على Mock محلي** (فارغ `DATABASE_URL` / `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`) على المنفذ `3130` عبر `npx next dev -p 3130` (لاحظ: `npm run dev -- -p 3130` معروف أنه يفشل).

## ٣. البند ١٨ — ضغط الصور أكثر (WebP) + تحميل كسول + وصف عربي لكل صورة

### الحالة الحالية
- `next/image` مستخدم في `components/PropertyCard.tsx`، `app/stay/[slug]/page.tsx`، `app/checkout/page.tsx`، `app/owner/units/[id]/preview/page.tsx`، `components/ImageOrderEditor.tsx`.
- `<img>` عادي في `components/DocumentUpload.tsx` و`app/owner/profile/page.tsx` (صور توثيق الهوية — للمراجعة فقط).
- الرفع: ضغط عميل إلى ١٦٠٠px JPEG ٨٢٪ (`lib/client-image.ts`) ثم Cloudinary بـ `width:1600,height:1200,crop:limit` (`lib/cloudinary.ts`)، سقف ٤MB.
- `Property.images` مصفوفة روابط فقط **بدون حقل alt لكل صورة** → أي وصف مخصص يحتاج تغيير DB (خارج النطاق).

### التنفيذ المقترح (بدون تغيير DB)
1. **مانيفست أصول** في `docs/IMAGE-ASSETS.md`: جدول لكل صورة منشورة: `publicId` / الرابط / الوصف العربي / المقاس المستهدف / ترتيب الغلاف. يُنتج من البيانات الحالية ويُحدَّث يدوياً عند إضافة وحدة.
2. **وصف عربي تلقائي لكل صورة** عبر دالة `propertyImageAlt(property, index)` في ملف جديد `lib/image-assets.ts`:
   - الغلاف: `صورة لوحدة «${property.name}» في ${CITIES[property.city].ar}`.
   - الباقي: `صورة رقم ${n} لوحدة «${property.name}» في ${CITIES[property.city].ar}`.
   - تُطبَّق على البطاقات والمعرض والدفع والمعاينة و`ImageOrderEditor` بدل `alt={property.name}` و`alt={\`${name} ${i+2}\`}`.
   - صور التوثيق تستخدم الـ `label` العربي الممرّر إليها (تبقى كما هي لأسباب خصوصية).
3. **WebP/ضغط أقل:** دالة `cloudinaryDeliveryUrl(url, width)` في نفس الملف تُدخل `f_auto,q_auto,w_<width>` بعد `/image/upload/` لروابط `res.cloudinary.com` فقط، وتكون **idempotent** (ما تضيفش تحويلين)، وترجع الرابط كما هو لأي مضيف آخر. `next/image` يكمل الباقي بصيغة WebP الافتراضية + `srcset`.
4. **تحميل كسول:** `loading="lazy"` و`decoding="async"` على كل الصور غير البطاقة الأولى/غلاف الوحدة؛ الغلاف يبقى `preload` (كما هو اليوم) لأنه LCP. صور الـ ٤ في المعرض والبطاقات والدفع والمعاينة تصبح lazy.
5. **لا Three.js ولا 360° ولا GSAP.** فكرة الـ tilt/Swipe المؤثرة تُترك كخيار منفصل بعد موافقة صريحة.

### خطوات التجربة
- على Mock: فحص كل `<img>` في `/search` و`/stay/[slug]` عبر المتصفح: `alt` غير فارغ وعربي، `loading="lazy"` على غير الغلاف.
- فحص شبكة التحميل: روابط Cloudinary فيها `f_auto,q_auto`، و`Content-Type` يرجع `image/webp` أو `image/avif` عندما يدعم المتصفح.
- Lighthouse قبل/بعد لصفحة وحدة إن توفرت أداة المتصفح (قياس فعلي مش تخمين).
- `typecheck` / `lint` / `build`.

### قرار مطلوب منك
الوصف التلقائي المشتق من اسم الوحدة والمدينة **بدون حقول DB جديدة**. لو عايز المالك يكتب وصفاً مخصصاً لكل صورة، ده تغيير schema محتاج بند مستقل وموافقة.

## ٤. البند ١٩ — SEO: عنوان ووصف وصورة مشاركة لكل وحدة + sitemap

### الحالة الحالية
- `app/layout.tsx` فيه title template ووصف عام، لكن **لا `metadataBase` ولا canonical ولا OpenGraph**.
- `app/stay/[slug]/page.tsx` فيه `generateMetadata` بسيط: `title` و`description.slice(0,155)` فقط.
- `NEXT_PUBLIC_SITE_URL` موجود في `.env.example` وREADME، و`lib/notifications.ts` فيه fallback للنطاق الحقيقي.
- `Property` **لا يحتوي `updatedAt`** → لا يوجد تاريخ تعديل حقيقي للـ `lastmod`.

### التنفيذ المقترح
1. **الجذر:** `metadataBase` من `NEXT_PUBLIC_SITE_URL` مع fallback `https://qiwalo-ygzh.vercel.app`، و`robots` عام، وفتح `openGraph.siteName = "قيوالو"` و`locale = "ar_EG"`.
2. **صفحة الوحدة:** توسيع `generateMetadata`:
   - عنوان: `اسم الوحدة | المدينة` (القالب في الجذر يضيف `| قيوالو` تلقائياً — بدون تكرار).
   - وصف عربي يتضمن المدينة ونوع الوحدة والسعر المبدئي والمرافق المميزة (≤ ١٦٠ حرفاً، بدون تلميح بـ«توفر مؤكد»).
   - `alternates.canonical: /stay/<slug>`.
   - `openGraph`: `type: "website"`، `locale: "ar_EG"`، `siteName`، `title`، `description`، `images: [صورة غلاف بمقاس ١٢٠٠×٦٣٠ عبر Cloudinary f_auto,q_auto,c_fill,g_auto]`.
   - `twitter: { card: "summary_large_image", ... }`.
   - إن لم توجد صورة غلاف → صورة افتراضية ثابتة داخل `public/` (شارة قيوالو) بدل رابط مكسور.
3. **JSON-LD اختياري (مجاني):** سكربت `LodgingBusiness` بالاسم والوصف والمدينة والسعر و`aggregateRating` فقط لو `reviewCount > 0` — يُحقن من السيرفر في صفحة الوحدة. (أضيفه كجزء من البند ١٩ إلا إذا قلت «لا»).
4. **`app/sitemap.ts`:** الصفحات العامة فقط (`/`, `/search`, `/terms` + ٤ مستندات، `/privacy`, `/favorites`) + الوحدات **`PUBLISHED`** عبر `repo.listProperties({ status: "PUBLISHED" })`. **`lastmod` يُثبَّت** إلى `2026-11-25` (أو يُحذف للوحدات) لأن مفيش `updatedAt` في الـ schema — ما نضيفش عمود DB من غير موافقة.
5. **`app/robots.ts`:** `Allow: /` مع `Disallow` على `/admin`, `/owner`, `/checkout`, `/booking`, `/payment`, `/login`, `/forgot-password`, `/reset-password`, `/api/`, و`Sitemap: https://qiwalo-ygzh.vercel.app/sitemap.xml`.

### خطوات التجربة
- Mock: `GET /sitemap.xml` و`GET /robots.txt`؛ التأكد إن الوحدات غير المنشورة والصفحات الخاصة **غير موجودة**.
- `GET /stay/<slug>`: البحث في HTML عن `og:title`، `og:description`، `og:image`، `twitter:card`، `rel=canonical`، وJSON-LD صالح.
- بعد الدفع للإنتاج: نفس الفحص على النطاق الحقيقي (قراءة فقط).
- `typecheck` / `lint` / `build`.

### قرار مطلوب منك
إضافة **JSON-LD** نعم ولا لا؟ (أنصح بـ نعم، مجانية وما تلمسش البيانات.)

- التأكد إن الووركفلو يشتغل على push تجريبي في فرع (بعد موافقتك) وإن الـ artifact يظهر عند فشل متعمّد ثم يُزال.

### قرار مطلوب منك

## ٧. البند ٢٢ — قسم «رحلتك مع قيوالو» (Scrollytelling رأسي)

**اعتماد المستخدم:** الاسم المعتمد للمعالم هو **«معالم أسوان»** (مش أهرامات)، والترتيب المعتمد أدناه.

### التنفيذ المقترح
1. قسم في الرئيسية بعد الـ hero بعنوان `رحلتك مع قيوالو`: مشهد لاصق (`position: sticky`) يتحرك مع السكرول من مرحلة للتانية، من فوق لتحت:
   1. مطار — طيارة (وصول الأقصر/أسوان)
   2. النقل — عربية / أتوبيس من المطار
   3. الإقامة — شقة / فيلا / فندق
   4. **معالم أسوان** (فيلة، أبو سمبل، النيل)
   5. الفطار
   6. جولة النيل / استكشاف
   7. العشاء
   8. الرجوع + تقييم + زر «ابحث عن إقامة»
2. مكوّن `components/JourneyStory.tsx`: `IntersectionObserver` صغير لتحديد المرحلة النشطة + CSS للانتقالات (بدون GSAP / Three.js / Lenis). حالة `prefers-reduced-motion` توقف الحركة وتعرض كل المراحل ثابتة.
3. صور `next/image` بـ `loading="lazy"` و`alt` عربي لكل مرحلة، ونفس توكنات التصميم (كريم/كحلي/ذهبي). **لا DB ولا حزم مدفوعة.**
4. القسم تكميلي للبحث: ما ياخدش مكان زر البحث ولا يبطّئ الصفحة، و`cacheComponents` / `partialPrefetching` يفضلا شغالين.
